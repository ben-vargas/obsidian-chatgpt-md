# Contributing to ChatGPT MD

Thanks for helping improve ChatGPT MD. This guide is intentionally short so new contributors and AI coding agents can make safe, reviewable changes.

## Setup

```bash
npm install
```

The repository currently contains npm scripts and should be validated with npm commands.

## Validation

Run these before opening a PR or handing work to another agent:

```bash
npm run build
npm test -- --runInBand
npm run lint
```

`npm run lint` may report existing warnings about long/complex functions. Do not add new warnings when possible.

## Project map

- `src/main.ts` — Obsidian plugin entry point.
- `src/core/ServiceContainer.ts` — explicit service wiring.
- `src/Commands/` — command handlers and command registration helpers.
- `src/Services/AiProviderService.ts` — AI request facade; currently large, refactor incrementally.
- `src/Services/Adapters/` — provider-specific adapter implementations.
- `src/Services/SettingsService.ts` — plugin settings, migrations, effective frontmatter config.
- `src/Services/ToolService.ts` — AI tool registration, approval, execution, result formatting.
- `src/Views/` — Obsidian UI and modals.
- `src/Utilities/` — stateless helpers.
- `src/Models/` and `src/Types/` — internal data contracts.

## Pull request guidelines

- Keep changes small and focused.
- Prefer pure helper extraction over rewrites.
- Avoid formatting-only churn in unrelated files.
- Do not introduce new dependencies for simple logic.
- Preserve existing user settings and frontmatter compatibility.
- Include validation results in the PR description.

## Adding commands

1. Add a handler in `src/Commands/`.
2. Implement one of the interfaces in `src/Commands/CommandHandler.ts`.
3. Register it from `src/main.ts`, preferably through `CommandRegistrar`.
4. Keep command handlers as orchestration only; put reusable logic in services/utilities.

## Adding providers

Provider support currently uses a unified AI facade plus adapters:

- `src/Services/AiProviderService.ts`
- `src/Services/Adapters/*Adapter.ts`

Until a central provider registry is added, provider changes may also require edits to defaults, settings types, settings UI, command utilities, and frontmatter helpers. Search for an existing provider name before making changes.

## Settings and frontmatter compatibility

When adding or changing settings:

- Update `ChatGPT_MDSettings` and `DEFAULT_SETTINGS` in `src/Models/Config.ts`.
- Update the settings UI.
- Add a migration if existing users need data conversion.
- Preserve note-frontmatter override behavior unless intentionally changing it.

Effective chat configuration priority is:

1. provider defaults
2. default chat frontmatter
3. global settings
4. agent frontmatter/body
5. note frontmatter

## Security/privacy

- Never log API keys.
- Do not bypass tool approval flows.
- Do not expose vault or web-search data to an LLM without user approval.

## Generated/local files

Do not manually edit or commit:

- `coverage/`
- `.DS_Store`
- local editor/IDE state
- logs

`main.js` is generated by the build and may be used as a release artifact. Do not edit it by hand.
